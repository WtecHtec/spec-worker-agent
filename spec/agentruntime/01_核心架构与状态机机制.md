# Agent Runtime 核心架构与状态机机制设计规范

## 1. 架构定位与设计哲学

`agent-runtime` 是系统中完全由 **LangGraph SDK 体系**驱动的高性能、可断点恢复的全自主智能体运行时服务。
其核心原则为：
- **Thread-centric Single Source of Truth**：以 LangGraph Thread 与 Checkpointer 为唯一真理来源，状态完全受控；
- **平台级标准与解耦**：遵循 LangGraph API Server 规范，对外暴露标准 SSE 流式与控制接口；
- **沙箱与数据一致性**：沙箱文件操作直连 PostgreSQL，元数据与版本历史同步持久化。

## 2. 核心状态机与图编排拓扑（StateGraph Topology）

系统采用模块化装配设计（[agent.py]( /agent-runtime/agent.py)），构建高健壮性 ReAct 闭环：

```
       [START]
          │
          ▼
    ┌────────────┐
    │ agent_node │ ◄─────────────────────────┐
    └────────────┘                           │
          │                                  │
          ▼ (should_continue 路由判断)        │
     ┌────┴─────────────────┐                │
     │                      │                │
[有 tool_calls]         [无 tool_calls]      │
     │                      │                │
     ▼                      ▼                │
┌────────────┐           [END]               │
│ tools_node │                               │
└────────────┘ ──────────────────────────────┘
```

### 2.1 状态定义（AgentState）
定义于 [src/state/state.py]( /agent-runtime/src/state/state.py)：
```python
class AgentState(TypedDict):
    # 消息核心通道：使用 LangGraph 内置 add_messages reducer
    messages: Annotated[list[BaseMessage], add_messages]
    # 当前执行的任务 ID / 会话 ID
    task_id: Optional[str]
    session_id: Optional[str]
    # 人类协同决策上下文
    hitl_decision: Optional[dict[str, Any]]
```

### 2.2 节点职责划分
1. **`agent_node`**（[src/nodes/agent_node.py]( /agent-runtime/src/nodes/agent_node.py)）：
   - 动态注入系统提示词（System Prompt）；
   - 获取当前租户绑定的可用工具列表（`registry.get_tools()`）；
   - 驱动大模型（LLM）进行推理决策，输出文本或 `tool_calls`。
2. **`tools_node`**（[src/nodes/tools_node.py]( /agent-runtime/src/nodes/tools_node.py)）：
   - 逐个派发工具调用，支持异步并行；
   - 内置安全策略拦截（高危操作拦截）；
   - 内置 `interrupt()` 人机协同审批触发；
   - 格式化生成 `ToolMessage` 回注至图上下文。

## 3. 检查点（Checkpointer）与数据持久化

### 3.1 平台级与独立模式解耦
- **服务运行时（`langgraph dev` / `langgraph up`）**：
  遵循官方平台规范，代码导出 `graph = builder.compile()`，平台自动由底层接管持久化；
  通过环境变量 `POSTGRES_URI` 决定存储介质：
  - 配置 `POSTGRES_URI=postgresql://...`：全量 Checkpoints 自动落入 PostgreSQL（`checkpoints`, `checkpoint_writes`, `checkpoint_blobs` 表）；
  - 留空：自动在本地内存（`.langgraph_api`）快速调试。

### 3.2 沙箱写文件直连落库机制
在沙箱执行写文件（`sandbox_write_file`）时，[file_recorder.py]( /agent-runtime/src/db/file_recorder.py) 直连 PostgreSQL 数据库：
1. **外键关联**：根据 `thread_id` 反查 `sessions` 表自动关联真实 `user_id`；
2. **元数据推断**：自动识别文件分类（`code` / `html` / `document` 等）与 `mime_type`；
3. **双表同步落盘**：
   - `files` 表：执行唯一约束 `UPSERT`；
   - `file_versions` 表：追加生成自增版本号与操作日志。
