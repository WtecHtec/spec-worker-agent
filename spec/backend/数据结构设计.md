# Agent 系统数据结构设计

> 技术栈：PostgreSQL（持久化）+ Redis（队列 / 通知 / 锁）
> 场景：多用户、长任务、断点续传、HITL

---

## 实体关系总览

```
users
  └── 1:N ── sessions（会话）
                 └── 1:N ── messages（消息）
                               └── 1:0/1 ── tasks（异步任务）
                                               └── 1:N ── task_steps（步骤流水）
                                               └── 1:1 ── task_checkpoints（断点）
                                               └── 1:N ── hitl_requests（人工介入）

关键关系说明：
  - 一条用户消息可以触发 0 或 1 个异步任务
  - 任务完成后，结果以 AGENT 消息写回会话，用户可在对话流中看到
  - 会话保存对话上下文，任务保存执行上下文，职责分离
  - 用户关闭页面再打开，通过 session_id 恢复对话，通过 task_id 恢复任务进度
```

## 一、PostgreSQL 表结构

### 1. users（用户表）

```sql
CREATE TABLE users (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    external_id     TEXT UNIQUE,                     -- 第三方登录 ID（如 Google sub、GitHub id）
    auth_provider   TEXT,                            -- 登录方式（email / google / github）
    email           TEXT UNIQUE,
    display_name    TEXT,
    avatar_url      TEXT,

    -- 配额控制
    plan            TEXT NOT NULL DEFAULT 'free',    -- free / pro / enterprise
    max_concurrent_tasks INTEGER NOT NULL DEFAULT 3, -- 最多同时运行几个任务
    monthly_token_quota  BIGINT NOT NULL DEFAULT 100000,
    token_used_this_month BIGINT NOT NULL DEFAULT 0,
    quota_reset_at  TIMESTAMPTZ NOT NULL DEFAULT (date_trunc('month', NOW()) + INTERVAL '1 month'),

    -- 状态
    status          TEXT NOT NULL DEFAULT 'active',  -- active / suspended / deleted
    last_active_at  TIMESTAMPTZ,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_external ON users(external_id, auth_provider);
```

---

### 2. sessions（会话表）

```sql
CREATE TABLE sessions (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id         UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title           TEXT,                            -- 会话标题（可由第一条消息自动生成）
    status          TEXT NOT NULL DEFAULT 'active',  -- active / archived / deleted

    -- Agent 配置（每个会话可绑定不同角色 / 工具集）
    agent_config    JSONB NOT NULL DEFAULT '{}',
    -- 示例：{ "model": "gpt-4o", "system_prompt": "你是...", "tools": ["web_search"] }

    -- 统计（冗余字段，避免频繁 COUNT）
    message_count   INTEGER NOT NULL DEFAULT 0,
    last_message_at TIMESTAMPTZ,

    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_sessions_user_id ON sessions(user_id);
CREATE INDEX idx_sessions_user_active ON sessions(user_id, last_message_at DESC)
    WHERE status = 'active';  -- 用户拉取会话列表走此索引
```

### 3. messages（会话消息表）

```sql
CREATE TABLE messages (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id      UUID NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
    role            TEXT NOT NULL,     -- USER / AGENT / SYSTEM / TOOL
    content_type    TEXT NOT NULL DEFAULT 'text',  -- text / task_reference / error
    content         JSONB NOT NULL,    -- 消息内容（结构见下方说明）

    -- 关联任务（这条消息触发了异步任务时写入）
    task_id         UUID,              -- 外键在 tasks 创建后再加，避免循环依赖

    -- 消息状态
    status          TEXT NOT NULL DEFAULT 'done',   -- done / streaming / failed

    -- 用自增序号排序，避免 UUID 乱序
    seq             BIGINT NOT NULL GENERATED ALWAYS AS IDENTITY,

    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- role 枚举：
-- USER      → 用户发送的消息
-- AGENT     → Agent 回复（含任务结果摘要 or 直接回复）
-- SYSTEM    → 系统事件通知（任务开始/完成/HITL 等）

-- content 结构示例：

-- USER / text：
-- { "text": "帮我分析最近的销售数据" }

-- AGENT / task_reference（触发任务时先占位，任务完成后更新）：
-- {
--   "text": "好的，我已开始执行，预计 3-5 分钟",
--   "task_id": "abc-123",
--   "task_status": "RUNNING"
-- }
-- 任务完成后 UPDATE messages SET content = { ..., "task_status": "COMPLETED", "summary": "..." }

-- AGENT / text（直接回复，无需任务）：
-- { "text": "根据你的描述，建议你..." }

-- SYSTEM / text（任务状态变化时自动插入一条）：
-- { "text": "任务执行完成", "task_id": "abc-123", "event": "task_completed" }

CREATE INDEX idx_messages_session_seq ON messages(session_id, seq);
CREATE INDEX idx_messages_task_id ON messages(task_id) WHERE task_id IS NOT NULL;
```

### 4. tasks（任务主表）

```sql
CREATE TABLE tasks (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id         UUID NOT NULL REFERENCES users(id),
    session_id      UUID REFERENCES sessions(id),    -- 归属会话（非对话式任务可为空）
    trigger_message_id UUID,                         -- 触发此任务的消息 ID（建立后回填）
    title           TEXT,                            -- 任务标题（用户可读）
    input           JSONB NOT NULL,                  -- 用户原始输入
    status          TEXT NOT NULL DEFAULT 'PENDING', -- 任务状态（见状态枚举）
    priority        INTEGER NOT NULL DEFAULT 0,      -- 优先级（越大越优先）

    -- Worker 相关
    worker_id       TEXT,                            -- 当前持有任务的 Worker 标识
    worker_heartbeat TIMESTAMPTZ,                   -- Worker 最近一次心跳时间

    -- 结果
    result          JSONB,                           -- 最终输出（完成后写入）
    error           TEXT,                            -- 失败原因

    -- 时间
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    started_at      TIMESTAMPTZ,                     -- Worker 第一次开始执行的时间
    completed_at    TIMESTAMPTZ                      -- 完成/失败时间
);

-- 状态枚举说明：
-- PENDING         → 已创建，等待 Worker 取任务
-- RUNNING         → Worker 正在执行
-- WAITING_HUMAN   → 触发 HITL，等待用户响应
-- PAUSED          → 主动暂停（如服务升级时优雅退出）
-- COMPLETED       → 成功完成
-- FAILED          → 执行失败
-- CANCELLED       → 用户主动取消

CREATE INDEX idx_tasks_user_id ON tasks(user_id);
CREATE INDEX idx_tasks_status ON tasks(status);
CREATE INDEX idx_tasks_worker_heartbeat ON tasks(worker_heartbeat) 
    WHERE status = 'RUNNING'; -- 用于监控服务扫描僵尸任务
```

### 2. task_steps（步骤执行流水）

```sql
CREATE TABLE task_steps (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    task_id         UUID NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
    step_index      INTEGER NOT NULL,               -- 步骤序号，从 1 开始，前端排序用
    type            TEXT NOT NULL,                  -- 步骤类型（见类型枚举）
    content         JSONB NOT NULL,                 -- 步骤内容（结构见下方说明）
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    UNIQUE (task_id, step_index)                    -- 同一任务内步骤序号唯一（幂等写入依赖此约束）
);

-- 步骤类型枚举：
-- THINKING        → Agent 的推理过程（LLM 内部思考）
-- TOOL_CALL       → 调用工具（发起阶段）
-- TOOL_RESULT     → 工具返回结果
-- HITL_REQUEST    → 需要人工介入
-- HITL_RESPONSE   → 人工响应结果（写入记录，方便回放）
-- SUMMARY         → 阶段性摘要（上下文压缩时产生）
-- FINAL           → 最终输出

-- content 结构示例（按 type 区分）：
-- THINKING:    { "text": "用户想要分析销售数据，我需要先..." }
-- TOOL_CALL:   { "tool_name": "web_search", "arguments": { "query": "..." }, "idempotency_key": "abc-5-search" }
-- TOOL_RESULT: { "tool_name": "web_search", "output": {...}, "duration_ms": 320 }
-- HITL_REQUEST:{ "hitl_request_id": "uuid", "question": "是否继续？", "type": "choice" }
-- FINAL:       { "text": "分析完成，结论是..." }

CREATE INDEX idx_task_steps_task_id ON task_steps(task_id);
CREATE INDEX idx_task_steps_task_step ON task_steps(task_id, step_index);
```

### 3. task_checkpoints（断点续传）

```sql
CREATE TABLE task_checkpoints (
    task_id             UUID PRIMARY KEY REFERENCES tasks(id) ON DELETE CASCADE,
    last_completed_step INTEGER NOT NULL DEFAULT 0,  -- 最后完成的步骤序号
    version             INTEGER NOT NULL DEFAULT 1,  -- 乐观锁版本号，防并发写冲突

    -- LLM 上下文恢复材料（分层存储）
    recent_messages     JSONB NOT NULL DEFAULT '[]', -- 最近 N 步的原始对话记录
    context_summary     TEXT,                        -- 更早历史的摘要
    task_variables      JSONB NOT NULL DEFAULT '{}', -- 任务中间变量（key-value）

    -- 幂等性保障
    completed_tool_calls JSONB NOT NULL DEFAULT '[]', -- 已成功执行过的 idempotency_key 列表

    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- recent_messages 示例：
-- [
--   { "role": "assistant", "content": "我需要先搜索资料" },
--   { "role": "tool", "name": "web_search", "content": "搜索结果..." },
--   { "role": "assistant", "content": "根据结果，我接下来..." }
-- ]

-- task_variables 示例：
-- { "found_articles": 10, "target_email": "user@example.com", "draft_title": "..." }
```

### 4. hitl_requests（人工介入请求）

```sql
CREATE TABLE hitl_requests (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    task_id         UUID NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
    step_index      INTEGER NOT NULL,               -- 在哪一步触发的

    -- 问题定义
    type            TEXT NOT NULL,                  -- 交互类型（见枚举）
    question        TEXT NOT NULL,                  -- 问用户什么
    options         JSONB,                          -- 可选项（type=choice 时使用）
    form_schema     JSONB,                          -- 表单结构（type=form 时使用）
    default_action  TEXT,                           -- 超时后的默认处理（cancel / proceed）

    -- 状态
    status          TEXT NOT NULL DEFAULT 'PENDING',-- PENDING / RESOLVED / EXPIRED / CANCELLED
    expires_at      TIMESTAMPTZ NOT NULL,           -- 超时时间

    -- 用户响应
    user_decision   TEXT,                           -- 用户的选择（choice 类型）
    user_input      JSONB,                          -- 用户的输入内容（text/form 类型）
    responded_at    TIMESTAMPTZ,                    -- 用户响应时间

    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- type 枚举：
-- choice      → 单选（确认/取消/选A/选B）
-- text_input  → 自由文本输入
-- file_upload → 上传文件
-- form        → 复杂表单（多字段）

-- options 示例（type=choice）：
-- [
--   { "value": "confirm", "label": "确认继续" },
--   { "value": "cancel",  "label": "取消任务" },
--   { "value": "modify",  "label": "修改参数" }
-- ]

CREATE INDEX idx_hitl_task_id ON hitl_requests(task_id);
CREATE INDEX idx_hitl_status_expires ON hitl_requests(status, expires_at) 
    WHERE status = 'PENDING'; -- 定时任务扫描超时用
```

### 5. 辅助：updated_at 自动更新触发器

```sql
-- 复用函数，所有表共用
CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_tasks_updated_at
    BEFORE UPDATE ON tasks
    FOR EACH ROW EXECUTE FUNCTION set_updated_at();

CREATE TRIGGER trg_checkpoints_updated_at
    BEFORE UPDATE ON task_checkpoints
    FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```

## 二、Redis 数据结构

### 1. 任务队列（Redis Stream）

> 选择 Stream 而不是 List，因为 Stream 天然支持消费者组（多 Worker 竞争消费）和 ACK 机制

```
Key:    task_queue
Type:   Redis Stream

消息体（每条消息的 fields）：
{
  "task_id":    "uuid-abc-123",
  "user_id":    "uuid-user-456",
  "priority":   "10",
  "resume_from_step": "0",      -- 0 表示全新任务，>0 表示断点恢复
  "enqueued_at": "2024-01-01T12:00:00Z"
}

消费者组：
  XGROUP CREATE task_queue workers $ MKSTREAM

Worker 消费：
  XREADGROUP GROUP workers worker-1 COUNT 1 BLOCK 5000 STREAMS task_queue >

Worker 完成后 ACK：
  XACK task_queue workers <message-id>

-- 未 ACK 的消息在 Worker 崩溃后可以被重新分配
-- XAUTOCLAIM task_queue workers worker-2 60000 0-0
--            ↑ 60秒未 ACK 的消息转移给 worker-2
```

---

### 2. 实时通知（Redis Pub/Sub）

```
Channel 命名规则：  task:{task_id}
Type:              Pub/Sub

Worker 发布消息：
  PUBLISH task:abc-123 <消息体 JSON>

SSE Handler 订阅：
  SUBSCRIBE task:abc-123

消息体结构：
{
  "event":      "new_step",       -- 事件类型
  "task_id":    "abc-123",
  "step_index": 5,
  "step_type":  "TOOL_RESULT"     -- 前端可以预判渲染样式
}

-- 注意：消息体不携带 content 本身
-- SSE Handler 收到通知后去 PostgreSQL 查 content
-- 原因：避免 Redis 消息过大，且 PostgreSQL 才是唯一数据源

其他事件类型：
  "task_status_changed"  → 任务状态变更（如进入 WAITING_HUMAN）
  "hitl_created"         → 新的 HITL 请求
  "task_completed"       → 任务完成
  "task_failed"          → 任务失败
```

---

### 3. 分布式锁

```
Key:    task_lock:{task_id}
Type:   String
Value:  {worker_id}（哪个 Worker 持有这把锁）
TTL:    60s（Worker 每 15s 续期一次，3 次心跳丢失才超时）

加锁（SET NX）：
  SET task_lock:abc-123 "worker-uuid-1" NX EX 60
  -- NX: 不存在才设置（互斥）
  -- EX: 60秒自动过期（兜底，防止锁泄漏）

续期（Worker 心跳）：
  EXPIRE task_lock:abc-123 60
  -- 仅在锁还属于自己时才续期（先 GET 验证 value）

解锁（原子操作，用 Lua 脚本）：
  if redis.call("GET", key) == worker_id then
      redis.call("DEL", key)
  end
  -- 防止误删别人的锁

Worker 写 Checkpoint 时的乐观锁：
  UPDATE task_checkpoints
  SET ..., version = version + 1
  WHERE task_id = ? AND version = ?  -- 版本号不对则写入 0 行
  -- 影响行数为 0 → 说明被其他 Worker 抢先，当前 Worker 主动退出
```

---

### 4. 用户任务列表缓存（可选）

```
Key:    user_tasks:{user_id}
Type:   Sorted Set
Score:  created_at 时间戳
Value:  task_id

用途：快速返回用户的任务列表，不用每次扫全表

用户打开页面：
  ZREVRANGE user_tasks:user-456 0 19  -- 最近 20 个任务

任务创建时写入：
  ZADD user_tasks:user-456 <timestamp> <task_id>

TTL：不设，或按业务需要定期清理
```

## 三、SSE 事件格式

### 推送给前端的 SSE 事件体

```
SSE 协议格式（文本流）：

event: new_step
data: {"step_index":5,"type":"TOOL_RESULT","content":{"tool_name":"web_search","output":{...}},"created_at":"..."}

event: task_status_changed
data: {"task_id":"abc-123","status":"WAITING_HUMAN","hitl_request_id":"hitl-uuid"}

event: hitl_created
data: {"hitl_request_id":"hitl-uuid","type":"choice","question":"是否继续删除 500 条记录？","options":[{"value":"confirm","label":"确认"},{"value":"cancel","label":"取消"}],"expires_at":"..."}

event: task_completed
data: {"task_id":"abc-123","result":{"text":"任务执行完成，结论是..."}}

event: task_failed
data: {"task_id":"abc-123","error":"LLM 调用超时，已重试 3 次"}

event: ping
data: {}
-- 每 30s 发一次，防止连接被中间件断开
```

### SSE 接口约定

```
GET /tasks/{task_id}/stream?from_step=N

参数说明：
  from_step  可选，默认 0
             前端传入"已收到的最后一个 step_index"
             服务端补发 step_index > from_step 的历史步骤后，再实时推新步骤

响应头：
  Content-Type: text/event-stream
  Cache-Control: no-cache
  X-Accel-Buffering: no  -- 关闭 Nginx 缓冲，保证实时性
```

## 五、Worker 内部处理逻辑（伪代码层面的数据流）

```
取到任务消息（从 Redis Stream）：
  message = { task_id, resume_from_step: 0 }

获取分布式锁：
  SET task_lock:{task_id} {worker_id} NX EX 60

加载上下文（从 PostgreSQL）：
  checkpoint = SELECT * FROM task_checkpoints WHERE task_id = ?
  context = rebuild_llm_context(checkpoint)

执行循环（每一步）：
  step_result = call_llm_or_tool(context)

  写入步骤（幂等）：
    INSERT INTO task_steps (task_id, step_index, type, content)
    ON CONFLICT (task_id, step_index) DO NOTHING  -- 幂等保障

  更新 Checkpoint：
    UPDATE task_checkpoints
    SET last_completed_step = ?, version = version + 1, ...
    WHERE task_id = ? AND version = ?
    -- 影响行数为 0 → 版本冲突 → 退出

  通知 SSE Handler（Redis Publish）：
    PUBLISH task:{task_id} '{"event":"new_step","step_index":N}'

  心跳续期（Redis）：
    EXPIRE task_lock:{task_id} 60
    UPDATE tasks SET worker_heartbeat = NOW() WHERE task_id = ?

  判断是否 HITL：
    if step_result.needs_human:
      INSERT INTO hitl_requests (...)
      UPDATE tasks SET status = 'WAITING_HUMAN'
      PUBLISH task:{task_id} '{"event":"hitl_created",...}'
      XACK task_queue workers {message_id}  -- 确认消费
      break  -- Worker 主动退出，释放锁

任务完成：
  UPDATE tasks SET status = 'COMPLETED', result = ?, completed_at = NOW()
  PUBLISH task:{task_id} '{"event":"task_completed"}'
  XACK task_queue workers {message_id}
  DEL task_lock:{task_id}
```
