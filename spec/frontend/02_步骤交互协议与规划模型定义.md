# 02. 前端交互步骤协议定义与规划模型规范

## 一、 步骤交互协议枚举 (StepType)

后端通过 SSE（Server-Sent Events）及 `/steps` 接口向前端推送结构化步骤事件，标准数据结构如下：

```typescript
export interface TaskStep {
  id: string;
  task_id: string;
  step_index: number;
  type: StepType;
  content: Record<string, any>;
  wait_for_human: boolean;
  created_at: string;
}

export type StepType =
  | "PLAN_GENERATED"  // 首次生成宏观计划
  | "PLAN_UPDATED"    // 动态重规划更新计划
  | "THINKING"        // 思考链推理文本
  | "TOOL_CALL"       // 触发工具调用
  | "TOOL_RESULT"     // 工具执行结果与耗时
  | "HITL_REQUEST"    // 人工决策挂起请求
  | "FINAL";          // 最终交付成果
```

## 二、 规划模型协议定义 (Plan Protocol)

### 1. `PLAN_GENERATED`（初次创建计划）
当 Planner 拆解用户任务后，推送该事件：

```json
{
  "step_index": 1,
  "type": "PLAN_GENERATED",
  "content": {
    "goal": "分析竞品功能并编写自动化测试套件",
    "analysis": "任务分为信息抓取、依赖配置、测试用例编写与运行三个主要环节。",
    "current_step_id": 1,
    "is_replan": false,
    "steps": [
      {
        "id": 1,
        "title": "抓取目标网页情报",
        "description": "调用 fetch_webpage 获取竞品 API 文档与功能列表",
        "status": "in_progress",
        "result_summary": null
      },
      {
        "id": 2,
        "title": "在沙箱中编写测试代码",
        "description": "调用 sandbox_write_file 写入 test_spec.py",
        "status": "pending",
        "result_summary": null
      },
      {
        "id": 3,
        "title": "运行测试并输出研报",
        "description": "调用 sandbox_run_command 执行 pytest 并汇总报告",
        "status": "pending",
        "result_summary": null
      }
    ]
  },
  "wait_for_human": false
}
```

### 2. `PLAN_UPDATED`（动态重规划/修复计划）
当某个步骤失败（例如环境依赖缺失）时，Planner 动态调整后续步骤并推送该事件：

```json
{
  "step_index": 6,
  "type": "PLAN_UPDATED",
  "content": {
    "goal": "分析竞品功能并编写自动化测试套件",
    "analysis": "由于 Step 2 执行时发现沙箱中缺失 requests 库，动态插入依赖安装步骤。",
    "current_step_id": 2,
    "is_replan": true,
    "steps": [
      {
        "id": 1,
        "title": "抓取目标网页情报",
        "description": "调用 fetch_webpage 获取竞品 API 文档与功能列表",
        "status": "completed",
        "result_summary": "成功获取 15 条竞品特性列表"
      },
      {
        "id": 2,
        "title": "安装缺失的 Python 依赖 (动态插入)",
        "description": "调用 sandbox_run_command 执行 pip install requests pytest",
        "status": "in_progress",
        "result_summary": null
      },
      {
        "id": 3,
        "title": "在沙箱中编写测试代码",
        "description": "调用 sandbox_write_file 写入 test_spec.py",
        "status": "pending",
        "result_summary": null
      },
      {
        "id": 4,
        "title": "运行测试并输出研报",
        "description": "调用 sandbox_run_command 执行 pytest 并汇总报告",
        "status": "pending",
        "result_summary": null
      }
    ]
  },
  "wait_for_human": false
}
```

## 三、 前端渲染架构：动态顶置看板 + 时间轴

前端 [StepContainer.tsx](/frontend/src/components/steps/StepContainer.tsx) 对步骤数据进行解耦渲染：
1. **顶部固定动态看板**：提取最新的 `PLAN_GENERATED` / `PLAN_UPDATED`，由 [PlanStep.tsx](/frontend/src/components/steps/PlanStep.tsx) 单卡片呈现，步骤进度（`pending` / `in_progress` / `completed` / `failed`）实时动态响应；
2. **中间与底部执行时间轴**：按时间序过滤并展示 `THINKING`、`TOOL_CALL`、`TOOL_RESULT` 与 `HITL_REQUEST`；
3. **底部最终输出**：展示 `FINAL` 最终结论。
