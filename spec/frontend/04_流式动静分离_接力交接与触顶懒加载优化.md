# 前端流式动静分离、接力交接与触顶懒加载设计规范

## 1. 背景与核心痛点

在大模型高频推流（每秒 20 ~ 50 个 Token）场景下，传统全量平铺渲染存在三大顽疾：
1. **历史气泡反复 Diff**：每次 Token 更新导致全量历史消息重新参与虚拟 DOM 比对，引发 CPU 占用飙升与掉帧；
2. **打字与历史混淆**：进行中的临时打字态与完成的历史态没有清晰界限，切换易闪烁或出现双倍重复消息；
3. **触顶跳跃**：长会话向上滚动加载更早历史时，DOM 节点插入顶部导致滚动条位置失控跳顶。

---

## 2. 核心架构创新与落地

### 2.1 动静分离（Static History + Active Streaming Leaf）
- **拆分原则（[messageNormalizer.ts]( /frontend/src/lib/messageNormalizer.ts)）**：
  ```typescript
  export function splitCompletedAndActive(
    rawMessages: any[],
    isStreaming: boolean
  ): { completedTurns: NormalizedTurn[]; activeTurn: NormalizedTurn | null }
  ```
  - `completedTurns`：已完成的历史交互轮次，在整个推流打字期间**数组引用保持稳定，历史组件重绘次数直接降为 0**；
  - `activeTurn`：当前正在运行的 Agent 轮次。
- **独立叶子组件（[ActiveStreamingTurn.tsx]( /frontend/src/components/chat/ActiveStreamingTurn.tsx)）**：
  专职渲染当前正在执行的工具步骤（可展开折叠）与流式打字正文，内部通过 `requestAnimationFrame` 进行 16.6ms 垂直同步节流，高频 Token 在此局部完全自我消化。

---

### 2.2 动静无缝接力交接（Seamless Handoff）
- **状态流转**：
  1. 用户发送消息：推入 `completedTurns` 作为最新用户气泡，底部挂载 `<ActiveStreamingTurn />`；
  2. 服务端推流进行中：历史气泡完全静止，底部独立叶子卡片高频打字；
  3. 推流结束（`onFinish`）：`activeTurn` 自然完结，原子性收敛进 `completedTurns` 成为最新的历史静态卡片，同时卸载流式组件。
- **成效**：交接瞬间**0 闪烁、0 跳跃、0 重复数据**。

---

### 2.3 触顶真实拉取与滚动位置锚定（Scroll Anchoring）
- **真实数据库分页查询**：
  基于官方 SDK 的 `await client.threads.getHistory(threadId, { limit, before })` 向后端真实拉取更早的 Checkpoint 快照链；
- **滚动高度差补偿锚定算法（[ChatWindow.tsx]( /frontend/src/components/chat/ChatWindow.tsx)）**：
  ```typescript
  // 1. 请求注入前记录旧高度
  const prevScrollHeight = container.scrollHeight;

  // 2. 注入数据库更早历史消息
  setDatabaseMessages((prev) => [...olderMessages, ...prev]);

  // 3. 在下一渲染微任务精准补偿 scrollTop
  requestAnimationFrame(() => {
    const newScrollHeight = container.scrollHeight;
    const diff = newScrollHeight - prevScrollHeight;
    container.scrollTop += diff;
  });
  ```
- **成效**：用户当前阅读视口内的消息**绝对静止**，更早的历史在上方自然静默展开，彻底消灭“跳顶”问题。
