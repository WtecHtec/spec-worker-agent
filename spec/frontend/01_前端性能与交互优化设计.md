# 01. 前端性能与交互体验深度优化设计

## 一、 性能优化：按需懒加载消除 N+1 请求风暴

### 1. 痛点问题
在会话消息列表中，每一条 Agent 消息都包含底层的子任务步骤记录。如果历史会话有 50 条消息，首屏进入时如果全量挂载 `StepContainer` 并发发起 `GET /tasks/{id}/steps`，会引发 **50 次并发 HTTP 洪峰**，造成浏览器连接池排队与后端连接暴涨。

### 2. 解决方案：流式直出 + 历史按需折叠抽屉
* **当前流式任务（`isStreaming === true`）**：保持实时直出，直接挂载 `StepContainer` 并开启 SSE 长连接；
* **历史已完成任务（`COMPLETED` / `FAILED` / `CANCELLED`）**：
  * 卡片主体直接渲染最终文本（`message.content.text`），**首屏进入时发起 0 次额外 HTTP 请求**；
  * 底部提供轻量折叠按钮 `[ ⚡ 展开执行过程与工具调用 ]`；
  * 仅当用户主动点击展开时，才触发请求并拉取步骤数据。

```
【用户打开包含 50 条消息的历史会话】
                │
                ▼
        ┌─────────────────┐
        │  只拉取消息列表  │ ───▶ HTTP 请求数：1 次 (降低 98%+)
        └─────────────────┘
                │
                ├────────────────────────────────┐
                ▼                                ▼
       【普通历史消息展示】                 【用户点击某条消息展开】
    - Markdown 渲染最终成果              - 挂载 StepContainer
    - 0 次步骤网络请求                  - 首次拉取并缓存至 Zustand
                                       - 二次折叠展开 0ms 纯内存命中
```

## 二、 交互体验优化

### 1. 结构化 Markdown 富文本与代码块
* **Markdown 排版**：接入 `ReactMarkdown`，支持标题、列表、引用与表格。
* **高亮与一键复制**：接入 `CodeBlock`，根据语言高亮语法，并提供悬浮复制按钮与已复制反馈。

### 2. Framer-Motion 动效与加载状态
* 折叠展开使用 `<AnimatePresence>` 与 `<motion.div>` 保证高度自适应弹性动画过渡。
* 步骤首次拉取时展示毛玻璃骨架与加载微动画，消除空白闪烁。
